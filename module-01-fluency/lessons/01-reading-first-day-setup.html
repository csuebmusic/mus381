Part 1 · the Mac and Finder

If you've never used a Mac before, this part is for you. If you have, use it as a refresher.

the basics of the screen

  • The bar across the top is the menu bar. The words there change depending on what app you're using.
  • The bar at the bottom (or side) with icons is the Dock. Click an icon there to open its app.
  • The space behind everything is the Desktop.
Don't save work to the Desktop

The Desktop on the lab computers gets cleared periodically, and anything saved there will be lost. Always save your work to ~/Documents/netid/, not to the Downloads folder or anywhere else. We'll set up that netid folder shortly.

open Finder

  1. Look at the Dock at the bottom of the screen.
  2. Find the icon that looks like a blue and white smiley face. That's Finder.
  3. Click it once. A window opens. This is how you look at files on the computer.

make a folder

The next few steps are a quick practice run: we'll make a throwaway folder on the Desktop, drop a file in, and delete it. Your real work goes in your ~/Documents/netid/ folder, which we'll set up shortly.

  1. In the Finder window, click Desktop in the left sidebar.
  2. From the menu bar at the top, click File, then New Folder. (Or hold Cmd + Shift + N.)
  3. A new folder appears called "untitled folder," with the name highlighted.
  4. Type test and press return. The folder is now called test.
  5. Double-click test to open it. It's empty.

take a screenshot

  1. Hold Cmd + Shift + 4 at the same time.
  2. Your cursor turns into a small crosshair.
  3. Click and drag a rectangle around any part of the screen. When you let go, the screenshot is saved.
  4. By default, the screenshot saves to your Desktop. Look there to find it.

rename the screenshot

By default, screenshots get a long name with spaces and capital letters, something like Screenshot 2026-08-19 at 3.21.45 PM.png. Rename it to follow the naming rules in Part 3.

  1. Click the screenshot icon on your Desktop once to select it.
  2. Press return. The name becomes editable.
  3. Type my-screenshot and press return again.

The new name is all lowercase, with a hyphen where the space was.

move the screenshot into the folder

  1. Click and hold the screenshot icon on your Desktop.
  2. Drag it on top of the test folder.
  3. Release. The screenshot disappears from the Desktop and is now inside the folder.
  4. Double-click test to confirm it's in there.

throw the folder away

  1. Click the test folder once to select it.
  2. Press Cmd + delete. The folder moves to the Trash.

show file extensions

A file extension is the part of a file name after the dot, like .wav, .mp3, .png. By default the Mac hides extensions. With them showing, you can tell a .wav from an .mp3 at a glance. Turn them on:

  1. Make sure Finder is the active app (click any Finder window).
  2. From the menu bar, click Finder, then Settings.
  3. Click the Advanced tab.
  4. Check the box that says Show all filename extensions.
  5. Close the Settings window.

Closing vs. quitting on a Mac

On a Mac, clicking the red dot at the top-left of a window only closes the window: the app keeps running in the background. To quit an app, use Cmd + Q, or go to the app's menu (the bold name at the top-left of the menu bar) and choose Quit. Two audio apps left running at once can conflict over the same audio interface.

Part 2 · set up your folders

In this class, you'll keep two copies of your work: a local copy on the computer you're using, and a master copy on the class server. You work in the local copy during a session. When you sit at a different station next session, you'll download your work from the server to that computer.

Today we'll create the local folder, then connect to the server and find the folder already made for you there.

The server is reachable from the lab only

Plan your work around that: anything you want at a different station next session has to be uploaded before you leave this one, and anything you want at home has to go on a USB drive or your own cloud storage.

make your local folder

  1. Open Finder.
  2. In the left sidebar, click Documents.
  3. Press Cmd + Shift + N to make a new folder.
  4. Name it with your NetID, lowercase, the same one you sign in to Canvas with. Press return.
  5. Double-click the folder to open it.
  6. Press Cmd + Shift + N again to make another new folder. Name it week-01.

Today's work goes in week-01.

FileZilla and the class server

The class server is a computer in the building that holds everyone's work. You reach it with an app called FileZilla, already installed on every lab computer. Its window is split down the middle: this computer on the left, the server on the right. You move work between them by dragging from one side to the other.

The server uses SFTP (secure file transfer protocol). The address you type starts with sftp://.

The FileZilla project keeps a short guide at wiki.filezilla-project.org/Using. Four of its sections apply to us: Using the Quick Connect bar, Navigating on the server, Navigating on your machine, and Transferring files. Its troubleshooting section is written for Windows machines.

connect to the server

  1. Hold Cmd + Space, type FileZilla, press return.
  2. Across the top of the window is the Quickconnect bar: four small fields and a button. Fill them in:
    • In Host, type sftp://134.154.190.239.
    • In Username, type your NetID.
    • In Password, type your NetID password, the same one you use for Canvas and campus email.
    • In Port, type 22.
  3. Click Quickconnect.
  4. A message appears about an unknown host key. Tick Always trust this host, add this key to the cache, then click OK. Without the tick you'll see this dialog on every connection.

Text scrolls past in the panel at the top: that's FileZilla reporting what it's doing. When it settles, the right side of the window fills with the contents of your own folder on the server, created for you and named with your NetID. Today it's empty.

Your folder and the shared folder

What you see on the right when you connect is yours alone. Class material and the work your classmates post for peer review are in a separate folder called public. To get there, click the / at the top of the directory tree on the right side, then open public. We'll use it starting in Module 2.

If something goes wrong

The most common problem is a typo in the host address, or a NetID password typed from muscle memory for a different account. Retype both carefully, watching for the sftp:// at the front. If you still can't connect, raise your hand. Your instructor will help.

disconnect for now

You'll reconnect at the end of class to upload your work. For now, choose Server → Disconnect from the menu bar, then quit FileZilla with Cmd + Q.

FileZilla on the lab computers doesn't save passwords. You type yours at the start of every session.

Part 3 · file and folder names

Follow these rules for every file and folder you name in this class, starting today.

the rules

  • Use lowercase letters only.
  • Put a hyphen where you'd put a space: my-project, not My Project.
  • Leave out special characters such as &, !, @, #, $, %, (, ).
  • Give each file a descriptive name, one that tells you what's inside without opening it.
  • Save versions: when you make changes, save as v1, then v2, rather than overwriting.

the format for this class

lastname-projectname-version.ext

Examples:

thiebaut-hello.m4a
smith-soundpiece-v1.wav
garcia-fieldrec-traffic.wav
How software reads file names

Different software and operating systems treat capital letters, spaces, and special characters differently. A file named My Project (final!).wav can open on one machine and fail on the next.

Part 4 · set up your gear and make a recording

Take your time, and do these steps in order. Out of order, you can get a blast of sound in your ears or a distorted recording.

take today's gear from storage

From the lab's gear storage, take three things today: an audio interface, a pair of headphones, and a dynamic mic with its stand and an XLR cable. Carry them back to your station and set them on the desk. Don't plug anything in yet.

The same cycle every session

You'll do this take-out, plug-in, unplug, stow cycle every session. The Session Routines reference card at your station summarizes it, and today we'll go through it together. The mic comes out today for recording. Module 2 sessions use only the interface and headphones, for Audacity work. The mic comes back in Module 3 for the recording labs, and Module 4 adds a MIDI keyboard for sessions that use one.

what's now on your desk

  • The USB hub is the small box with several USB ports. It's already at your station, connected to the computer behind the monitor. Leave the hub itself plugged in, and unplug only the cables plugged into it.
  • The audio interface is the box with knobs. It converts between analog sound (from a mic, to your headphones) and digital data the computer can work with.
  • The microphone is a tabletop dynamic mic on a small stand. It connects to the audio interface with the XLR cable (the thick three-pin cable).
  • The headphones are over-ear, with a small in-line volume slider on the cable. You'll plug them into the audio interface in Step 2.

Step 1 · turn the interface knobs all the way down

Before plugging anything in or putting headphones on, find these three knobs on your audio interface and turn each one all the way down (counterclockwise, to zero):

  • The gain knob (sometimes labeled "Input" or with a number; there's one per input channel) controls how much the interface boosts the mic signal coming in.
  • The main / output knob (sometimes labeled "Monitor" or "Output") controls how loud the audio plays back to monitors and headphones.
  • The headphone knob (labeled with a headphones icon) controls headphone volume.
Knobs to zero, every time

If a cable is loose or something is set wrong, plugging in can send a sudden loud burst of sound into your ears and the gear. Turn every knob to zero before any plugging in or out, in this class and anywhere else you use audio gear.

Step 2 · plug everything in

  1. Plug the audio interface's USB cable into any open port on the USB hub.
  2. Plug the microphone's XLR cable into the input on the front of the audio interface (the round 3-pin socket).
  3. Plug your headphones into the headphone jack on the audio interface (labeled with a headphones icon). The jack is on the front or the back of the interface, depending on the model. Look for the icon.

You can leave the headphones around your neck for now. You won't hear anything in them until the gain is set, a few steps from now.

Step 3 · slide the headphone volume control all the way up

The headphones in the lab have a small in-line volume slider on the cable itself. Slide it all the way up right now. You'll set your listening volume with the headphone knob on the interface. With the slider anywhere below maximum, you'll hear little or nothing, whatever the knob is set to.

If you can't hear anything later

Check this slider first. It's the most common reason headphones seem silent.

Step 4 · verify the interface is connected

  1. Hold Cmd + Space. A search bar opens in the middle of the screen.
  2. Type Audio MIDI Setup and press return. The app opens.
  3. On the left, you'll see a list of audio devices. The name can be confusing: the Behringer U-Phoria UM2 shows up as USB Audio CODEC, not as "Behringer," while the PreSonus AudioBox USB 96 shows up as AudioBox USB 96. Find the one at your station, and if you're not sure which it is, raise your hand.
  4. Right-click your interface in the list, and click Use this device for sound input. The UM2 shows up as two separate entries here; the input is USB Audio CODEC 2. (The AudioBox is a single entry that handles both.)
  5. Right-click again, and click Use this device for sound output. On the UM2, the output is the other entry, USB Audio CODEC 1.
  6. With your interface still selected, find the Format line in the middle of the window and confirm it reads 48,000 Hz, the rate this course uses. If it shows something else, click the Format dropdown and pick a 48,000 Hz option. On the UM2, check both entries: USB Audio CODEC 2 (input) and USB Audio CODEC 1 (output). The clip below shows where to look.
  7. Quit Audio MIDI Setup: from the menu bar at the top, click Audio MIDI Setup, then Quit Audio MIDI Setup. (Or press Cmd + Q.)

That Format line is the interface's recording format: a couple of numbers that describe the audio it captures. You'll learn what they mean in Module 2. The two interfaces in this room show different choices there: the clip above is the Behringer, and the PreSonus gives you more options in the same place. Whichever one is at your station, that's where you'll find its format.

If your interface isn't listed

Unplug the USB cable from the hub, wait a moment, and plug it back into a different port on the hub. If still nothing, raise your hand.

Step 5 · open QuickTime and start a new audio recording

QuickTime is our level meter today: its meter shows how strong the mic signal is.

  1. Hold Cmd + Space, type QuickTime Player, press return.
  2. QuickTime opens. (If it shows a dialog asking what to open, close it.)
  3. From the menu bar, click File, then New Audio Recording.
  4. A small window appears with a red record button in the middle.
  5. Click the small downward arrow just to the right of the red button.
  6. From the menu, pick your audio interface as the source.

You'll see a horizontal level meter under the record button. Right now it's flat: the gain is still at zero.

Step 6 · bring up your headphone monitoring

Headphone monitoring lets you hear yourself before you record.

  1. Put the headphones on.
  2. Slowly turn up the headphone knob on the interface to about noon (12 o'clock, the knob pointing straight up).
  3. Slowly turn up the main / output knob on the interface to about noon as well.

You probably won't hear anything until the gain is set in Step 8.

Step 7 · set the mix knob or the Direct Monitor button

About half of the interfaces in the lab have an extra knob labeled Mixer, Mix, or Direct/USB. If yours has a Direct Monitor button instead (the Behringer UM2 does), press it in to hear your mic in the headphones, and skip the rest of this step.

If yours does have the knob, it controls what you hear in your headphones. On one side is the direct input (the live sound coming from your mic right now). On the other side is the computer playback (sound coming back from QuickTime, Audacity, or whatever software is running).

  1. Find the knob labeled Mixer, Mix, Direct/USB, or with arrows pointing to two sides.
  2. Set it to about 60% toward the direct/input side, 40% toward the computer/playback side. Roughly the 11 o'clock position if "direct" is on the left.
What 60/40 gives you

At 60/40 you hear mostly your live mic signal (the direct input), with no delay, plus a little of any playback the computer sends, such as a click track or backing audio. Module 3 comes back to this.

Step 8 · set the gain by talking and watching the meter

Here you set how strong the mic signal is when it reaches the computer.

  1. Speak at normal volume into the mic. Keep talking: say what you had for breakfast, count to twenty, anything.
  2. While talking, slowly turn up the gain knob on the interface.
  3. Watch QuickTime's level meter. As you turn up the gain, the meter will start moving with your voice.
  4. Stop turning up when the meter is regularly moving but never hitting all the way to the right. Aim for roughly half to two-thirds across.
  5. You should also be hearing yourself in the headphones now. If it's too loud or too quiet, adjust the headphone knob.
What you're doing

This is gain staging: setting the input level high enough for a strong, useful signal and low enough that it doesn't distort. Module 3 covers it in depth, when we focus on recording. For today, a moving meter is good, and a meter pinned all the way to the right is too hot: turn the gain down.

Step 9 · record

  1. Click the red record button.
  2. Say your name and one word about why you're taking this class.
  3. Click the same button (now a stop button) to stop.
  4. Click the small play button to listen back. If you hear yourself clearly, it worked.

Step 10 · save the file to your local folder

  1. From the menu bar, click File, then Save.
  2. A save dialog opens.
  3. In the Name field, type lastname-hello (your own last name, in lowercase).
  4. In the sidebar of the save dialog, click Documents.
  5. Navigate into your netid folder, then into week-01.
  6. Click Save.

The file is now saved locally. Your recording went through the whole audio signal chain: mic, cable, interface, gain, software, file.

before you leave today · the exit routine

Lab computers and gear are shared, and the room gets reset for the Art department between our class meetings. Before you leave, upload your work to the class server and stow the gear back in the lab's gear storage. The Session Routines reference card at your station has this routine for every session.

upload to the server

  1. Make sure your work is saved (Cmd + S in whatever app you used).
  2. Open FileZilla and connect again with the Quickconnect bar: sftp://134.154.190.239, your NetID, your NetID password, port 22.
  3. On the left side, navigate to ~/Documents/netid/. On the right side, stay in your own folder on the server.
  4. Click into the left side, select everything (Cmd + A), and drag it across into the right side.
  5. If FileZilla asks about files that already exist, choose Overwrite if source newer, tick Always use this action and Apply to current queue only, and click OK.
  6. Watch the transfer queue along the bottom of the window. When it empties and your file appears under Successful transfers, you're done. The right side should now show week-01/lastname-hello.m4a.
  7. Choose Server → Disconnect, then quit FileZilla (Cmd + Q).
The overwrite dialog

FileZilla asks what to do whenever a file exists on both sides. Overwrite if source newer is the choice in both directions: downloading, it takes the server's copy when the server is ahead; uploading, it takes today's work over last session's. Always use this action applies your choice to every file in the transfer. Apply to current queue only, next to it, limits that choice to this transfer, and FileZilla asks again on your next one.

sign out and quit

  1. Sign out of any browser accounts (Canvas, Google, Microsoft, etc.) and quit your browser (Cmd + Q).
  2. Quit all other apps with Cmd + Q. Look at the Dock: any app with a small dot under its icon is still running.

gear

  1. Turn the audio interface knobs (gain, main / output, headphone) all the way back to zero.
  2. Unplug each piece of gear: headphones from the interface, the interface's USB from the hub, the mic's XLR from both the mic and the interface. Coil any cables loosely; don't kink them.
  3. Return everything to the lab's gear storage: interface, headphones, mic, mic stand, XLR cable.
  4. Chair in.
