Step 1 · get the recording off your phone

You'll move the file with LocalSend, a free app that sends files between devices on the same Wi-Fi network. It's already installed on the lab Macs. If it isn't on your phone yet, install it now: App Store (iPhone) or Google Play (Android). Open it once and allow the permissions it asks for.

  1. On the lab Mac, open LocalSend from the Applications folder. It opens on the Receive tab, which shows this Mac's LocalSend name: two words, like Clever Banana. If macOS asks whether LocalSend can find devices on your local network, click Allow.
  2. On your phone, turn airplane mode off and connect to the campus Wi-Fi.
  3. In your recording app, find the recording, tap its share button, and choose LocalSend. (If LocalSend isn't in the share list, open LocalSend instead, go to the Send tab, tap File, and pick the recording.)
  4. Under Nearby devices, tap the Mac's LocalSend name.
  5. On the Mac, click Accept. The file saves to your Downloads folder.
  6. In Finder, move the file from Downloads into ~/Documents/netid/.
If the Mac doesn't show up

Check that your phone is on Wi-Fi and out of airplane mode. On an iPhone, open Settings → Privacy & Security → Local Network and make sure LocalSend is switched on. If the Mac still isn't listed, ask your instructor.

Other phone apps

If you've been recording with a different app (the iOS Voice Memos app, or a different Android recorder), LocalSend works the same way: share the file from that app to LocalSend. The file format may differ from what the recommended apps produce: Voice Memos produces M4A, not WAV. Audacity opens M4A directly, and the rest of today's procedure still applies. MP3 also works. M4A (at Voice Memos' default Compressed setting) and MP3 are both lossy formats: they throw away some audio detail to make the file smaller. When the app gives you the choice, pick WAV, which keeps all of it.

Step 2 · open Audacity, pull your library down

Pull your library down before you import the phone recording.

  1. Download your sample-library/ folder to your local working folder. (Same routine as every Wednesday; the Session Routines card has it. On the server it's sample-library/ inside your own folder. Local destination: ~/Documents/netid/sample-library/.)
  2. Open Audacity. Confirm the project format is still 48000 Hz / 24-bit PCM in Audacity → Preferences → Audio Settings.
  3. Save a new project file for today's work: File → Save Project → Save Project As…, and save it as sample-library-week-07.aup3 inside ~/Documents/netid/sample-library/audacity-projects/.
A note on the project rate

The project's sample rate (the one you just confirmed in Audio Settings) sets the rate for playback and for any new recordings made inside the project. It's separate from the sample rate of an individual track imported into the project. The two might match or might not; Step 4 covers the case where they don't.

Step 3 · import the phone recording

  1. Click anywhere in the empty Audacity project window to make sure it's the active window.
  2. From the menu bar: File → Import → Audio… (or Cmd + Shift + I). Navigate to ~/Documents/netid/ and select the phone recording. Click Open.
  3. The waveform appears as a new track in the project.
  4. Press spacebar to play it back. Confirm it sounds like what you remember recording. If it doesn't, you probably grabbed the wrong file off the phone; check the filename and try again.

To see the file's properties, open the Audio Track Dropdown Menu: click the three dots (…) next to the track's name in the Track Control Panel (the gray box on the left), or right-click anywhere on the track header. Hover over Format to see the bit depth, and over Rate to see the sample rate. The checked entries are what the track currently is. For a recording made with the recommended phone apps, this will be 48000 Hz and 24-bit PCM, which is exactly your project's format. The rates match, so there's nothing to convert: go straight to the prep pipeline in Step 5. (If a file ever shows a different rate, Step 4 covers it.)

Stereo or mono?

Phone recordings may be stereo (two channels: left and right) or mono (one channel) depending on the app's pickup-pattern setting. If your track shows two waveform lanes stacked vertically, it's stereo. If it shows one, it's mono. Every sample in your library is a mono WAV (Project 2 sets this). If the track is stereo, mix it down before you prep it: Tracks → Mix → Mix Stereo Down to Mono. A mono file is half the size of a stereo one.

Step 4 · when a file isn't at 48 kHz

The phone apps record at 48 kHz, and so does Audacity when you record in the lab. This step covers files at another rate: a recording from another device, a clip from an older project, any file at 44.1 kHz or some other rate. Your library uses 48 kHz for every file.

two ways to change a track's rate

Sample rate is how many samples per second the recording stores. A 48 kHz file holds 48,000 samples for every second of sound; a 44.1 kHz file holds 44,100. Each sample is a number. The rate is the instruction that says how fast to read those numbers back out.

That instruction can be changed in two ways. You can reinterpret the track: tell Audacity to read the same samples at a different speed. Or you can resample the track: Audacity works out what the same sound would look like stored at the new rate and writes new samples to match. Reinterpreting is fast (Audacity changes a setting), and the sound changes audibly. Resampling is slower (Audacity runs a calculation across the whole track), and the sound keeps its pitch and length.

feel the difference

The experiment works on any track. Try it once even when today's files all match the project.

  1. Open the Audio Track Dropdown Menu (three dots … next to the track name) and hover over Rate. Note the rate that's currently checked.
  2. Press spacebar to play a few seconds of the recording. Listen, look at the waveform's length on the timeline. Then stop.
  3. Open the dropdown again, hover over Rate, and click 22050 (about half the usual rate). The waveform on the timeline visibly stretches out: the same samples, read at half the speed, now take twice as long.
  4. Press spacebar. The recording plays back slower and at a lower pitch.
  5. Press spacebar again to stop. Press Cmd + Z to undo the rate change. The track returns to its original rate and the waveform snaps back to its original length.

Changing the rate in the dropdown menu didn't resample the audio. It changed the rate setting Audacity uses to read the samples back. Read at roughly half their rate, the same samples take about twice as long to play out, and every sound in the recording drops in pitch by the same factor.

When you want to reinterpret

Changing the rate without resampling gives a tape-style speed-and-pitch shift. The sound goes faster and higher, or slower and lower, in a single fixed ratio. Composers use it often (it can turn a footstep into a stomp, or a voice into a creature), and you'll use it again as a deliberate technique.

You have to know which operation you're choosing. Not every DAW resamples imported audio automatically; some load the file at its native rate and play it at the project rate, which is the same speed-and-pitch shift you just heard, applied silently to everything that comes in. This causes trouble with downloaded loops, especially drum loops. A 44.1 kHz break dragged into a 48 kHz project plays back faster and higher than it was recorded, and a producer who doesn't check the file's sample rate against the project's may spend an hour wondering why their drums feel slightly off. Look at the rate of every file you import. If it matches the project, you're done. If it doesn't, choose: resample (keep the pitch and length) or reinterpret (use the shift musically).

resample a stray file to 48 kHz

When a file comes in at another rate and you want to keep it sounding the way it was recorded, resample it. Tracks → Resample… calculates new samples at the new rate. Pitch and length stay the same; only the number of samples per second changes.

  1. Click anywhere in the Track Control Panel (the gray box on the left of the track). The whole track highlights to show it's selected.
  2. From the menu bar: Tracks → Resample…
  3. The Resample dialog opens with a dropdown labeled New sample rate (Hz). Pick 48000. Click OK.
  4. Audacity processes the track. The waveform's length on the timeline stays the same; if you play it back now it sounds identical to before. Open the Audio Track Dropdown Menu and hover Rate: 48000 is now the checked entry, and the audio underneath has been resampled to match.
Two operations, two menus

The two operations are in two different places:

  • Audio Track Dropdown Menu → Rate → [pick a rate] changes the rate setting on the track. The samples stay the same and play back at a new speed. Pitch and length both shift.
  • Tracks → Resample… writes new samples at the new rate. Pitch and length stay the same.

Your library uses 48 kHz, and to match a stray file you always use Resample.

Step 5 · run the prep pipeline

The pipeline is the one from Lab 1: denoise → trim → normalize, with a short fade at each end after the trim. For a phone recording, the noise profile works differently.

about the noise profile

In Lab 1 you captured a dedicated 10-second noise-profile clip at the top of the project, recorded in the same room with the same mic at the same gain. The denoise step then used that profile to subtract the room's noise floor from the paper recordings.

A phone recording brings its own noise floor with it: whatever was in the room when you hit record, plus the phone's own electronic hiss. The noise profile has to come from the phone recording itself. Capture the profile from a quiet portion of the recording before or after the sound you want.

From this session on, record a second or two of silence at the start of every take, on phone or in the lab.

the pipeline

  1. Capture a noise profile from a quiet region of the phone recording (a second or two of silence before or after the sound itself). Select the region with the I-beam, open Effect → Noise Removal and Repair → Noise Reduction…, and click Get Noise Profile. The dialog closes. (If your recording has no quiet region anywhere, see the underwater callout below.)
  2. Denoise the whole clip: double-click it to select it and open Noise Reduction again. Set the sliders to 6, 6.00, 6 (a gentle starting point) if they aren't there already, and click OK.
  3. Trim to the sound itself: select just the sound with the I-beam, leaving the silence outside the selection, and choose Edit → Remove Special → Trim Audio (Cmd + T).
  4. Fade each end: zoom in (Cmd + 1) at the start, select about 50 ms, and apply Effect → Fading → Fade In. Zoom out (Cmd + F) and repeat at the end with Fade Out.
  5. Normalize the trimmed clip: double-click it, open Effect → Volume and Compression → Normalize…, set the peak to -1.0 dB with Remove DC offset checked, and click OK.

If any of these steps feels unfamiliar, open Lab 1's handout (Recording into Audacity) and refer to Step 8 there for the full walkthrough with screenshots.

If denoise is making the recording sound underwater

Phone-recorded noise is sometimes harder to subtract cleanly than lab-recorded noise. If the result of denoise sounds hollow, whispery, or has a swimming-pool quality, the profile probably caught some non-noise content (a faint sound, your finger brushing the phone, a passing voice). Undo the denoise (Cmd + Z), pick a different quiet region for the profile, and try again. If no part of the recording is quiet enough, skip the denoise step for this file. Trim, fades, and normalize still produce a usable sample, with its original noise floor still in it.

Step 6 · export to your library

Decide which folder in your library the sample goes in. The library's organized by category folders at the root: you already have paper/. For today's recordings, you'll probably want to add at least one more category. Pick a folder name that fits what you recorded.

Example categories:

  • kitchen/ for a kettle, water, ice, fridge, dishes
  • metal/ for a bike chain, keys, coins, hinges, latches
  • fabric/ for clothing, cushions, bags, anything soft
  • space/ or room/ for ambient recordings of places (a hallway, an elevator, a courtyard)
  • body/ for footsteps, claps, breathing, voice

The category is your call; the names above are starting points. The rule is the same as the paper/ folder: lowercase, hyphenated if needed, no spaces. Pick one you'll remember and that fits more sounds than today's.

  1. In Finder, create the new category folder inside ~/Documents/netid/sample-library/.
  2. Back in Audacity, double-click the prepped clip to select it.
  3. File → Export Audio… opens the Export dialog. Fill in:
    • Name the file in the File Name field with the convention [category]-[descriptor]-[variant].wav. The variant slot tells takes of the same descriptor apart (for example metal-keys-jangle.wav and metal-keys-drop.wav, or kitchen-kettle-boil.wav and kitchen-kettle-pour.wav). Every file uses all three slots, even when you have only one take of something.
    • For Folder, click Browse… and pick the category folder you just created.
    • Set Format to WAV (Microsoft).
    • Set Channels to Mono.
    • Set Sample Rate to 48000 Hz and Encoding to Signed 24-bit PCM.
    • Under Export Range, choose Current selection.
  4. Click Export. Leave the metadata dialog blank.

One sample is now in the library at its new path: for example, ~/Documents/netid/sample-library/kitchen/kitchen-kettle-boil.wav.

update the README

Open your library's README.txt in TextEdit. Add the new category to the ORGANIZATION section and the new file to the CONTENTS section. Update the Last updated: date at the top. Save.

The README isn't optional

Every time you add a sample, update the README the same day. The README is part of the midterm grade.
