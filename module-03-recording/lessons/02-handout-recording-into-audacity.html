Module 03 · Recording, sample prep & library building

recording into Audacity

Capture four sounds, prep them into samples, start your library.

Monday's reading covered the basic recording chain on paper. Today you plug it in, record four paper sounds (a crumble and a rip, each at two speeds), and start the sample library you'll add to for the rest of the semester.

today's gear

Take from the lab's gear storage: audio interface, headphones, dynamic mic (with stand and XLR cable). Plug in and run through the start-of-session steps on the Session Routines card before continuing here.

what we're doing today

  1. Set up your sample library folder.
  2. Configure Audacity for recording: project format, recording device, mono track.
  3. Set the gain knob on the interface using Audacity's input meter. Aim for peaks at -12 to -6 dBFS.
  4. Set the monitor mix to hear yourself while recording.
  5. Do a test recording. Listen back. Adjust if needed.
  6. Capture a short noise-profile clip (room tone) for the denoise step later.
  7. Record the four paper sounds.
  8. Prep each recording through the three-step pipeline: denoise → trim → normalize.
  9. Export each prepped sample as a WAV.
  10. Write the library README. Upload everything to the class server.
first time with the mic

The five-stage chain you read about Monday (mic → XLR cable → interface → USB cable → computer) is now physically in front of you. If anything looks wrong, or a cable won't plug in cleanly, raise your hand before forcing anything.

Step 1 · set up your sample library folder

Build the folder now, before you open Audacity. This folder holds every sample you record this semester.

  1. In Finder, navigate to your local working folder: ~/Documents/netid/. (If you don't have a folder there yet, make one named with your NetID, lowercase.)
  2. Inside that folder, create a new folder named sample-library. Lowercase, hyphenated. This is the library's root.
  3. Inside sample-library/, create a folder named paper. This is the first category folder; you'll add more categories (metal, water, voice, etc.) as you record more sounds in later weeks.
  4. Inside sample-library/, also create a folder named audacity-projects. Your working Audacity project file goes here (you'll save it in a few minutes).

Your folder should now look like this:

~/Documents/netid/
  sample-library/
    paper/                    <-- empty for now; samples go here in Step 9
    audacity-projects/        <-- empty for now; the .aup3 project goes here after the test recording

Step 2 · configure Audacity for recording

Open Audacity and check the audio settings before you record.

check the project format in Preferences

  1. Open Audacity → Preferences… (or Cmd + ,). The Preferences window opens.
  2. In the left sidebar, click Audio Settings.
  3. Confirm (or set) the Module 2 standards: Project Sample Rate at 48000 Hz, Default Sample Format at 24-bit PCM.
if your interface is the UM2

You just set the project to 24-bit, but the Behringer UM2 captures at 16-bit. (The PreSonus AudioBox captures at 24-bit.) Recording a 16-bit interface into a 24-bit project is fine: Audacity stores exactly what the UM2 sends in a 24-bit file, with no conversion. The file has 16 bits of real detail in a 24-bit container. The audible difference is the noise floor, which is about -96 dB at 16-bit, far below anything in the sounds you're capturing. Leave the project at 24-bit either way.

device settings are here too

The Audio Settings panel in Preferences also has Recording Device, Playback Device, and Recording Channels dropdowns. Day to day, you'll set them from the Audio Setup button in the main window, in the next section.

  1. Click OK to close the Preferences window.

select the audio interface as your recording device

  1. At the top of the Audacity window, find the Audio Setup button (marker 5 on the empty-project tour from your orientation lab).
  2. Click it. A dropdown opens with several sections: Host, Playback Device, Recording Device, Recording Channels.
  3. Under Recording Device, choose your audio interface. The PreSonus shows up as AudioBox USB 96; the Behringer UM2 shows up as USB Audio CODEC, not as Behringer. Pick whichever matches the interface you took from storage.
  4. Under Recording Channels, choose 1 (Mono).
  5. Under Playback Device, the interface should already be selected, and playback then goes through the interface to your headphones. If it isn't selected, select it now.

add a mono recording track

  1. From the menu bar, click Tracks → Add New → Mono Track.
  2. An empty mono track appears in the project. Your recording goes on this track.
mono

A dynamic mic plugged into one input on the interface is a mono source, a single channel of audio. Recorded to a mono track, it makes a file half the size of a stereo one. Stereo recording is for two mics or a stereo source.

Step 3 · set the gain on the interface

The gain knob on the audio interface sets how much the preamp amplifies the mic-level signal before the ADC converts it to digital (Monday's reading, section 5). The target: when you make the loudest version of the sound you're about to record, the peaks on Audacity's input meter reach the -12 to -6 dBFS band. If they're outside that band, adjust the gain.

The meter has three bands:

  • Below -12 dBFS, the signal is under the target and the recording will be quiet. Turn the gain up.
  • From -12 to -6 dBFS is the target: the peaks of your loudest sound should reach this band. You have headroom (room between your loudest moment and the digital ceiling), and the signal is well above the noise floor.
  • From -6 to 0 dBFS, the signal is approaching the ceiling and you're close to clipping. If the clip light on the interface flashes, the signal has already clipped. Turn the gain down.

To dial it in:

  1. Turn on live monitoring so the meter shows levels before you start recording. Click Audacity's recording level meter at the top of the window. (It's the meter on the right side of the top toolbar, with a small mic icon.) A small menu appears with two items: Enable Silent Monitoring and Options…. Click Enable Silent Monitoring. The meter goes live: it shows the signal coming in from the mic in real time, even though you're not recording yet. (The "silent" in the name means the audio isn't routed through Audacity to your headphones, only displayed on the meter; you'll still hear the mic through the interface's monitor mix, set in the next step.)
  2. Make a sound at the loudness you'll be aiming for. For the paper sounds, that means a test crumble or a quick test rip at roughly the speed and intensity you'll use for the real take. Use a small piece of scrap paper from the stack at your station, and save the four full sheets for the real recordings.
  3. Watch the meter. If the peaks stay under -12, turn the gain knob on the interface clockwise (up) a quarter-turn and try again. If the peaks reach the red zone or trip the interface's clip indicator, turn the gain counter-clockwise (down).
  4. Repeat until the loudest peaks reach the -12 to -6 band every time. Watch where the loud moments usually peak, and ignore a single stray spike.
silent monitoring

Audacity keeps the input meter dark unless it's recording or monitoring. Once Silent Monitoring is on, the menu item changes to Disable Silent Monitoring. Leave it on while you set gain.

don't normalize to fix a quiet recording

You might be tempted to undershoot the gain ("better safe than clipping") and plan to fix it in editing. Don't. A signal recorded too quietly has less detail above the noise floor, and amplifying it later brings the room noise up with it. Set the gain right at the source. Normalize, in the prep step later, evens out peak level across recordings made at a good level.

Step 4 · set the monitor mix

The interface's monitor mix sets what you hear in your headphones while you record: the live signal straight from the mic (no latency), the signal coming back from the computer (a few milliseconds late), or a mix of both.

Today you want to hear the mic directly, with little or no playback from the computer.

  • On a PreSonus AudioBox USB 96, turn the Mixer knob (between the second gain knob and the Main knob) about three-quarters of the way toward Inputs. You'll hear yourself in the headphones immediately.
  • On a Behringer U-Phoria UM2, press the Direct Monitor button in (the square button next to the input jacks). The button stays down, and you hear the live input.
  • If you can't hear yourself at all, check the headphone volume knob on the interface, then the in-line slider on the headphone cable, then the monitor mix setting above. The headphones plug into the interface (on the front of the Behringer, on the back of the PreSonus), not the computer.

Speak into the mic. You should hear yourself in the headphones with no perceptible delay. If you hear nothing with the Mixer knob turned toward Playback, turn it toward Inputs. If you hear an echo, Audacity's audible input monitoring is on: open Transport → Transport Options and click Enable audible input monitoring to uncheck it.

Step 5 · do a test recording

Before you commit to the four real recordings, do one practice take to confirm the chain is working end to end.

  1. Make sure the empty mono track from Step 2 is in the project. If it isn't, add one (Tracks → Add New → Mono Track).
  2. Click the red Record button in the transport toolbar (or press R).
  3. Wait one second, then speak a short phrase ("test recording, one, two, three").
  4. Click Stop (or press Space).
  5. A waveform appears on the mono track. Click Skip to Start (Cmd + Home), then Play (Space). Listen.

As you listen, check three things:

  • The recording should be clearly audible. If it's silent or very quiet, the gain may be too low (back to Step 3), or the recording device may not be set right (back to Step 2).
  • The sound should be clean, with no crackling or harshness. If you hear distortion, the gain is too high. Turn it down (Step 3) and try again.
  • A faint room hiss in the background is normal; a strong hum usually means the XLR cable is loose at one end. Push the cable in firmly at the mic and at the interface.

When the test sounds clean, delete the test clip: double-click it to select it, then press Delete. The empty mono track stays, ready for the real recordings.

save your work

Save the Audacity project now, before you capture the real recordings. File → Save Project As…, navigate to ~/Documents/netid/sample-library/audacity-projects/ (the folder you built in Step 1), name the project sample-library.aup3, click Save. From this point on, save every few minutes with Cmd + S.

Step 6 · capture a noise-profile clip

Every room has a noise floor: the small constant level of background sound from the ventilation, the computers, the building. Your ears tune it out most of the time, but a microphone picks it up along with the sound you want. Audacity's Noise Reduction effect can subtract it. To do that, it needs a clean recording of the noise alone, with no other sound mixed in. That recording is called a noise profile. Record it now:

  1. Stand still and quiet at your station. Don't touch the mic, the cable, or the table.
  2. Click Record.
  3. Wait 10 seconds.
  4. Click Stop.

You now have a 10-second clip of room tone on your track: your noise-profile clip. The waveform looks almost flat, with only the small wiggles of the room noise. Leave it where it is; you'll use it in the prep step.

one noise profile for all four sounds

You record room tone once, as its own clip, and set the noise profile from it once. Noise Reduction then uses that profile on each of the four sound clips.

Step 7 · record the four paper sounds

Pick up a sheet of paper from the stack at your station. You're going to record four short sounds, each as its own clip on the same mono track.

The four recordings, in order:

  1. For paper crumble, slow, crumble the sheet slowly into a ball over about 8 to 10 seconds. Let the small individual crackles and creases be audible.
  2. For paper crumble, fast, take a new sheet and crumble it as quickly as you can, in about 2 to 3 seconds: a burst of sound rather than a gradual one.
  3. For paper rip, slow, take a new sheet and rip it slowly down the middle over about 6 to 8 seconds. Keep the tearing audible the whole way through.
  4. For paper rip, fast, take a new sheet and rip it as fast as you can, in one quick motion.

For each recording:

  1. Hold the paper about 15 to 20 centimeters (6 to 8 inches) in front of the mic. Any closer and the proximity effect exaggerates the lows, and the sound turns boomy.
  2. Click Record.
  3. Wait one full second of silence, then make the sound.
  4. After the sound ends, wait one full second more, then click Stop.

Without that second of silence at each end, the very beginning or end of the sound can get cut off. Between recordings, listen back: click the clip you just made and press Space. If a recording didn't capture what you wanted, double-click the clip, press Delete, and record that one again. Move on once each recording sounds the way you intended.

Step 8 · run the prep pipeline on each recording

You have five clips on one track: a noise-profile clip first, then the four paper sounds. The prep pipeline turns each of the four sound clips into a sample: a clean, standardized file ready for the library and for later projects. The pipeline has three steps, applied in order: denoise → trim → normalize.

You'll go through it four times, once per sound. The noise-profile clip doesn't get prepped.

set the noise profile (once)

Before the first denoise, Audacity needs to learn what the room noise sounds like. The noise profile stays in memory until you change it or close the program.

  1. Double-click the noise-profile clip (the flat-looking first clip on the track). Double-clicking inside a clip selects that whole clip and nothing else.
  2. Open Effect → Noise Removal and Repair → Noise Reduction…
  3. The Noise Reduction dialog opens. Click the Get Noise Profile button.
  4. The dialog closes immediately. Audacity has stored the noise profile.

for each of the four sound clips

Now apply the three pipeline steps to each paper-sound clip in turn. Start with paper crumble, slow (the second clip on the track).

1. denoise

  1. Double-click the clip to select it.
  2. Open Effect → Noise Removal and Repair → Noise Reduction…
  3. The dialog opens with three sliders: Noise reduction (dB), Sensitivity, Frequency smoothing (bands). Start with 6, 6.00, 6, a gentle setting. Adjust by ear if needed.
  4. Click OK. Audacity subtracts the noise profile from the clip. The waveform may look slightly thinner in the quiet portions; the body of the sound should look mostly unchanged.

2. trim

  1. The clip still has the one-second silence buffer at the start and end. Trim it away now.
  2. With the selection tool active (the I-beam), click-and-drag to select just the sound itself (from where the sound starts to where it ends, leaving the buffer silence outside the selection).
  3. Apply Edit → Remove Special → Trim Audio, or use the shortcut Cmd + T. Trim (from Module 2) keeps the selected region and removes everything else in the clip.
  4. The clip now begins where the sound begins and ends where it ends.
fades

A hard trim almost always cuts the waveform mid-cycle, which produces an audible click at the start or end of the file. Smooth it out with a short fade at each end of the clip:

  1. Zoom into the start of the clip with Cmd + 1 (or Cmd + E after selecting near the edge) until you can see individual cycles of the wave. At the default zoom, 50 ms is too small to select cleanly.
  2. Select about 50 milliseconds at the start of the clip (click-and-drag with the I-beam).
  3. Apply Effect → Fading → Fade In.
  4. Zoom back out with Cmd + F (zoom to fit the whole project).
  5. Repeat at the end of the clip: zoom in, select about 50 ms, apply Effect → Fading → Fade Out, zoom back out.

The Fade In / Fade Out commands and the Cmd + E ↔ Cmd + F zoom pair are from Module 2.

3. normalize

  1. Double-click the trimmed clip to select it.
  2. Open Effect → Volume and Compression → Normalize…
  3. In the dialog, set Normalize peak amplitude to: -1.0 dB.
  4. Make sure Remove DC offset is checked. Leave Normalize stereo channels independently as is (it has no effect on a mono file).
  5. Click OK. Audacity scales the clip's amplitude until its loudest peak is at -1 dBFS. The waveform expands vertically; quiet parts stay quiet relative to loud parts.
normalize scales the whole clip

Normalize multiplies every sample value in the clip by the same amount. The shape of the sound stays the same and its size changes, along with the level of the loudest peak. Every sample in your library ends up with its peak at -1 dBFS.

Repeat for the other three sounds (paper crumble fast, paper rip slow, paper rip fast). Listen to each after you finish to confirm it sounds right.

Step 9 · export each sample as a WAV

Export each of the four prepped clips as its own WAV file into the paper/ folder of your library.

Audacity exports the whole project by default: one file with every clip on the track, the noise-profile clip included. To get one file per sound, select a clip first, then export with the export range set to the current selection.

For each of the four samples:

  1. Double-click the clip to select it.
  2. From the menu bar: File → Export Audio…
  3. The Export Audio dialog opens. Fill it in:
    • Set File Name to the sample's name, following the convention below.
    • Next to Folder, click Browse… and pick ~/Documents/netid/sample-library/paper/.
    • Set Format to WAV (Microsoft).
    • Set Channels to Mono.
    • Set Sample Rate to 48000 Hz.
    • Set Encoding to Signed 24-bit PCM.
    • Set Export Range to Current selection.
  4. Click Export. If a metadata dialog appears, leave it blank and click OK.

sample filenames

The naming convention for samples this semester:

[category]-[descriptor]-[variant].wav

Use lowercase letters, with hyphens between words and no spaces or special characters. For today's four sounds:

  1. paper-crumble-slow.wav
  2. paper-crumble-fast.wav
  3. paper-rip-slow.wav
  4. paper-rip-fast.wav

The category, paper, matches the folder name: paper/paper-crumble-slow.wav. The descriptor names what the sound is (a crumble, a rip). The variant distinguishes two takes of the same descriptor (slow, fast).

Step 10 · write the library README, upload to the server

A README is the document at the root of the library that says what's in it and how it's organized. You write the first version today and update it every time you add to the library.

  1. Open TextEdit (in the Applications folder or via Spotlight).
  2. From the menu bar: Format → Make Plain Text (or Cmd + Shift + T). The document is now a plain-text file, not a styled document.
  3. Paste in the template below and fill in the bracketed parts.
  4. Save as README.txt in ~/Documents/netid/sample-library/.
SAMPLE LIBRARY · [your name]
MUS 381 · Fall 2026

Started: Wed Wk 6, [date]
Last updated: [today's date]

ORGANIZATION

Samples are organized in category folders at the root of the library:
  paper/      Paper sounds (crumbles, rips)

Filename convention:
  [category]-[descriptor]-[variant].wav
  e.g. paper-crumble-slow.wav

All samples are mono, 48 kHz, 24-bit WAV.
All samples are prepped: denoised, trimmed, normalized to -1 dBFS.

CONTENTS

paper/  (4 samples)
  paper-crumble-slow.wav    Slow crumble of a sheet of paper, ~8 sec
  paper-crumble-fast.wav    Fast crumble, ~2 sec burst
  paper-rip-slow.wav        Slow tearing, ~7 sec
  paper-rip-fast.wav        Fast tearing, one motion

NOTES

[anything you want to remember about today's session, e.g.
 "the slow crumble took two tries; the first one was too fast"
 or "interesting how different the two rip speeds feel"]
keeping the README current

The library will grow to dozens of sounds by the end of the semester. Each time you add to it, give a new category folder a line under ORGANIZATION and each new file a line under CONTENTS describing the sound. In Module 4 you'll pick samples for the final project from these descriptions.
